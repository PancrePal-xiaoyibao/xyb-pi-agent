# 中国药物临床试验登记平台接入

平台：中国药物临床试验登记与信息公示平台（`www.chinadrugtrials.org.cn`）。
形态：本机 MCP 服务 `chinadrugtrials`，由 `xyb.trial-sources` 插件声明，随插件启用而可用。

**这个来源和别处不一样的地方**：站点校验浏览器会话，所以**必须有患者本人的会话才能抓**。
工具不代替登录、不绕过验证。会话过期是常态，过期后请患者本人重新复制一次。

覆盖范围、与其他来源的分工，见「中国试验来源接入」。本文只讲这处的操作细则。

| 维度 | 情况 |
|---|---|
| 覆盖 | 中国药物注册临床试验（含 IIT 之外的注册类） |
| 检索条件 | 关键词 + 登记号、适应症、方案编号、药物名称/类型、申请人、伦理委员会、研究者、参加机构、状态 |
| 产物 | 详情页原始 HTML、结构化 RAG JSON、平台原样 Word、响应留档 |
| 数据落地 | `~/.xyb-chinadrugtrials/`（本机，不进仓库） |
| 速度 | **逐条抓取**，每条间隔 1.5 秒，不是查缓存 |

## 一、工具与参数

工具是**按需激活**的。直接调用可能得到 `Tool ... not found`——这不是坏了，是还没激活。
先 `ToolSearch` 用工具名查一次（例如查 `search_trials` 或 `chinadrugtrials`），
返回 "Activated on-demand tools" 之后，**下一轮**才能调用。

### get_collector_status —— 先调它

排障第一步，不要靠猜。返回：

- `ready`：三项前置（Python、依赖、会话）是否都就绪
- `python`：用的是哪个解释器、版本
- `collector_deps`：采集器依赖是否装齐，缺什么
- `cookie.configured`：会话是否已配置、最近更新时间
- `archive`：本机已归档了哪些关键词、各多少条、上次抓取时间
- `next_steps`：还差什么、下一步做什么

### setup_environment —— 一次性准备环境

在数据目录下建 Python 虚拟环境并安装依赖（`requests`、`beautifulsoup4`）。
需要联网，约十几秒到一两分钟。已就绪时直接返回，不会重复装。

本机没有 `python3` 时会明确告诉你。macOS 可 `xcode-select --install`，
或从 python.org 安装后重试——**这一步只能由患者本人做**，工具装不了 Python。

### update_cookie —— 保存本人会话

把浏览器里对该站**实际搜索请求**「复制为 cURL」的完整命令粘进 `curl` 字段即可
（也可以直接粘 Cookie 字符串）。

- 工具会从 `-b` / `--cookie` / `-H 'Cookie: ...'` 里提取，通常 cURL 比单独响应头更完整
- 只写本机 `~/.xyb-chinadrugtrials/config.json`，权限 0600
- **不回显值**，不写日志、不写回答、不进提交
- 若提取出的字段里没有平台常见的会话字段，会提示可能不是站内请求的完整 Cookie

**红线**：不得替患者生成、猜测或复用他人 Cookie；不得尝试绕过验证码或反爬。
患者不在场就直接说明暂时查不了。

### search_trials —— 检索并归档

必填 `keywords`（默认「胰腺癌」），可选高级条件：`state`、`indication`、`reg_no`、
`case_no`、`drugs_name`、`drugs_type`（1=中药/天然药物，2=化学药物，3=生物制品）、
`appliers`、`communities`、`researchers`、`agencies`。

- `max_pages`：默认 **2**，每页约 10 条。页数越大越慢，**别一上来就拉全量**
- `incremental`：增量模式，正文没变化的记录不重写 JSON、不重复下载 Word

跑之前先跟患者说清楚要等一会儿（逐条抓取）。同一条件不要重复触发。

### sync_incremental —— 日常巡检

按上次 `search_trials` 用过的条件做增量同步：逐条比对正文指纹，只保存新增或内容有变化的。
**每日检查用这个，不要每次全量重抓。**

### get_trial_detail —— 取一条详情

按登记号取本机归档的完整详情（各章节字段）。`include_full_text` 默认为否——全文很长。

**只读本机归档，不会联网现抓**。归档里没有就如实说没有；需要现抓先跑 `search_trials`。
这一点很重要：不要把「本机没归档」说成「平台上没有这条试验」。

### list_archived —— 看本机有什么

列出已归档的登记号、题目、状态、药物、适应症。不联网。可按关键词目录过滤。

### verify_archive —— 核对归档完整性

逐条检查登记号是否都有原始 HTML、结构化 JSON、平台原样 Word 与响应留档。
抓取收尾、或怀疑缺文件时用。macOS 上还会核对由 `textutil` 生成的 `.docx`；
非 macOS 环境缺少 `.docx` 属预期，不算失败。

## 二、归档产物

`~/.xyb-chinadrugtrials/output/<关键词>/`

| 路径 | 内容 |
|---|---|
| `raw/<登记号>_detail.html` | 详情页原始 HTML，一切结构化数据的可追溯来源 |
| `json/<登记号>.json` | RAG 友好结构化数据：分节字段、全文、`content_hash` |
| `word/<登记号>.doc` | 平台原样字节（可能是 Word 2003 XML / WordML） |
| `word/<登记号>.docx` | macOS 上用 `textutil` 转的兼容版本（可缺） |
| `word/source/<登记号>.source.doc` | 服务器原始响应留档 |
| `state.json` | 按登记号存的内容指纹，增量同步靠它 |
| `summary.json` | 最近一次抓取的汇总 |

引用某条试验时，优先给**登记号 + 平台原文链接**，需要原文可指向本机 raw HTML。

## 三、故障排查

### 「反爬挑战页 / 缺少有效浏览器会话」

这是**会话失效**，不是「没有相关试验」。

站点会校验浏览器会话，触发挑战时返回的是验证页而不是结果表。工具会明确报出来，
并把原始日志尾部一并返回。处理：请患者本人重新在浏览器正常访问平台，
对**实际搜索请求**「复制为 cURL」，再 `update_cookie`。

**不得**把它解释成「检索结果为 0 条」，也不得尝试绕过验证。

### 「本机没有可用的 python3」

`setup_environment` 会指出。macOS 上通常在没装 Xcode 命令行工具的机器上出现。
这一步必须患者本人操作，工具装不了 Python。

### 「采集器依赖未装齐」

调 `setup_environment`。多失败在网络，可换国内镜像重试。

### `raw/` 有文件但 `json/` 为空

说明详情页解析没匹配上。先跑一次 `search_trials` 重新抓取（raw 会重建）；
仍为空则把登记号与 raw 路径报给维护者，不要自己改采集器。

### 原始 `.doc` 打不开

平台可能把 WordML 当 `.doc` 下发。macOS 用 `textutil` 生成的 `.docx`，或直接用 WPS / Microsoft Word 打开。

### 「增量同步没有下载 Word」

若这次记录是「正文未变化」，这是**预期行为**，不是失败。先确认历史输出里有没有对应文档。
`summary.json` 里的 `skip_count` 含义是「正文未变化」，不是「抓取失败」或「文件缺失」。

## 四、跨来源硬约束（与「临床试验助手」一致）

1. **来源可溯**：每条结论都能指回登记编号与原文，写明取自哪个来源、查的什么条件
2. **区分「没查到」与「查不到」**：会话失效、依赖缺失、工具报错，都要如实说明，不得含糊成「没有」
3. **跨来源数据不可混算**：本平台与 ChiCTR、Veeva CTV、ClinicalTrials.gov 的登记口径、
   字段、更新节奏都不同，不做合并统计、不互相比「谁更多」
4. **不做入组判断**：只列条件与差异，是否适合由研究医生结合病情判断；不给「建议参加」
5. **不做医院与医生排名**
6. **不预测生存期**，不把早期数据当结论
7. **机制未披露就写未披露**，不推断
8. 所有输出带免责声明：信息整理，不替代医生判断，不构成用药建议
