# 试验匹配进阶版

来源：`opencare-skillhub/clinical-trial-matching`（上游 v2.0.0，作者 CancerDAO，方法学参考 NCBI TrialGPT）。
上游未声明 LICENSE 文件，仓库归属本组织。本机适配：改写工具名，其余规则原样保留。

本文讲**方法学**；各数据源怎么接、参数与前置条件见「中国试验来源接入」与「中国药物临床试验登记平台接入」。
「临床试验助手」讲的是基础检索与呈现，本文是它的加强版：多了 8 维搜索计划、R1-R5 合规规则与 0 匹配替代策略。

---

## 一、先收齐患者档案

要拿到这些字段（缺的要明说缺，不要猜）：

```
癌种（如 PDAC / NSCLC / CRC）
分期
基因突变（如 KRAS G12D、BRCA2、MSI-H）
治疗史（每线：方案 / 结果 PR|SD|PD）
既往用药（具体药名）
ECOG 评分
```

**信息不齐也能做**，但要按 R5 规则如实标出「哪几项无法判断」。

---

## 二、8 维搜索计划（逐维都搜，别只搜一个）

| # | 维度 | 例子 |
|---|---|---|
| 1 | 疾病 + 突变特异 | `胰腺癌 KRAS G12D` |
| 2 | 泛实体瘤 / 篮子试验 | `solid tumor KRAS G12D` |
| 3 | 联合靶点 | `KRAS G12D 联合 免疫` |
| 4 | 通路 / 耐药策略 | `pan-RAS`、`RAS-ON inhibitor` |
| 5 | 穷举药物名 | 在研的 + 已批准的同靶点药，逐个搜 |
| 6 | 细胞治疗 | CAR-T、TIL、TCR-T |
| 7 | 免疫（后 PD-1） | 双抗、LAG-3、TIGIT |
| 8 | 中文单 token | ChiCTR 分词器脆弱，**一次一个词**，不要组合 |

## 三、三源检索

| 来源 | 工具 | 说明 |
|---|---|---|
| ClinicalTrials.gov | `xyb_trials_search` | 开箱可用，NCT 编号 |
| ChiCTR | chictr MCP 的 `search_trials` | 中国注册试验，ChiCTR 编号 |
| 中国药物临床试验登记平台 | `chinadrugtrials` MCP 的 `search_trials` | 中国药物注册试验，CTR 编号；需本人会话 |

工具是**按需激活**的：直接调用可能得到 `Tool ... not found`，先用 `ToolSearch` 查一次工具名，下一轮再调。

**ChiCTR 返回空时的回退顺序**（不要就此说"没有"）：
1. 换成单个 token 重试（`胰腺癌 BRCA` → `BRCA`）
2. 回退到 ClinicalTrials.gov，并叠加中文适应症描述
3. 最后可用检索方式找 `site:chictr.org.cn` 并**验证注册号格式**（ChiCTR + 数字串）

---

## 四、逐条做入排分析

对每个候选试验：

1. **验证登记号真实**——绝不虚构。只输出实际检索到的编号与链接
2. **入排标准逐条比对**——用 ✓ / ⚠️ / ✗ 标注，一条一条对，不概括
3. **风险注释**——点出该患者相关的耐药机制（如 KRAS G12C 继发 RAS/MAPK 通路激活）
4. **中心与联系方式**——只写来源里真实给出的，供患者自行联系

---

## 五、R1-R5 规则：命中就必须写出来

这五条是**可观测**的：命中了要在该试验条目下显式输出规则名与原因，不能只在心里判断。

| 规则 | 触发条件 | 降级到 | 写法 |
|---|---|---|---|
| **R1 同类药物史** | 试验排除"用过同类机制药物"且患者用过 | conditional | `[R1] 试验排除曾用 <同类>，患者已用过 <具体药>。降级为条件匹配。` |
| **R2 线数错配** | 试验限定治疗线数，患者已完成线数超出 | conditional / excluded | `[R2] 试验限 <X-Y> 线，患者已完成 <N> 线。硬限→排除，软限→条件匹配。` |
| **R3 适应症错配** | 试验主招瘤种与患者不一致 | conditional | `[R3] 试验主要瘤种为 <X>，患者为 <Y>。理论符合但非主招方向。` |
| **R4 器官功能边界** | 要求指标且患者在边界值 | conditional / excluded | `[R4] 要求 <指标 ≥/≤ X>，患者 <当前值>，距边界 <Δ>。±10% 内→条件匹配。` |
| **R5 信息缺失** | ≥2 项关键标准无法判断 | conditional + 列缺失项 | `[R5] 以下 <N> 项无法判断：<逐项列出>。` |

没命中任何规则的试验也要显式写：`触发的合规规则：无（R1-R5 均未命中）`。

## 六、输出红线（硬约束，违反即 bug）

| 禁止 | 改成 |
|---|---|
| 数值评分（"匹配度 85%""9.2/10"） | 叙述符合点与不符合点 |
| 排名（"最适合""Top 1"） | 按地理 / 瘤种 / 线数**分组**呈现，不排序 |
| **"推荐"这个词**（含"建议你参加""我建议""优先选 XX"） | "符合入排标准的试验""可以和医生讨论的选项" |
| 编造 NCT / ChiCTR / CTR 编号或 PI 联系方式 | 只写实际检索到的 |
| 直接入组指令（"你符合，去打这个电话"） | "如希望进一步评估，请把这份材料交给主管医生联系研究中心" |

「推荐」在中国医疗法规语境下会被认定为构成医疗建议，超出工具定位——中文同义词全部禁用。

每条试验条目必须含：登记号 + 原文链接、主要入选标准逐条比对、主要排除标准逐条比对、命中的 R 规则。

**报告顶部**（任何分析之前）与**底部**都要有免责声明：信息整理，不构成医疗建议，入组与否由研究机构独立审核。

---

## 七、Goals-of-Care：必须提缓和护理

满足任一条件时，**在试验列表之前**独立出一块缓和护理选项（不可省略、不可合并）：

- 已完成 ≥3 线治疗（含当前线）
- ECOG ≥3
- 预测生存期 <12 个月
- 患者主动说"治不动了""想停下"

写什么：缓和医疗门诊（说明它不等于放弃治疗，是症状管理与生活质量优化）、疼痛专科、心理支持（患者与家属都需要）、营养支持。
并给出哪些医生/科室可以讨论，**不点名推荐具体医院**。

---

## 八、0 匹配时不许只说"没找到"

必须至少给三条替代路径：

1. **篮子 / 伞式试验**——按机制而非瘤种招募的，给出至少 1 个真实登记号
2. **罕见肿瘤专科中心**——按城市/科室描述该找哪一类中心，不做医院排名
3. **文献检索路径**——给出可复制的检索式，如
   `PubMed: "<基因> <突变>" AND "<癌种> rare" AND "(case report OR clinical trial)"`
