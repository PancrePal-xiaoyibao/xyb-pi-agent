# 病案整理

来源：`opencare-skillhub/Medical-Record-Organizer`（上游 name: `patient-record-organizer`）。
上游未声明 LICENSE 文件，仓库归属本组织。

**本机可用程度：方法论层。** 上游原文依赖 OCR / 语音转写脚本与多个云服务密钥
（MinerU、SiliconFlow、DashScope）。客户端没有执行外部脚本的权限，所以这里保留的是
**流程与分类体系**——整理本身由对话完成；需要外接文字识别或录音转写时，如实说明暂不具备，
不要假装已经处理了。

---

## 安全边界（先摆在这里）

- 不做诊断
- 不给治疗建议
- 不替代医嘱和处方
- 只做「资料整理与结构化归档」

---

## 一、六步流程

### 第 1 步：接收与清点

让用户把资料给你（上传文件、或说明手里有什么）。**先把清单念回去让用户确认**：

```
收到 N 份资料：
- 化验单 X 张（血常规 X、生化 X、肿瘤标志物 X）
- 影像报告 X 份（CT X、MRI X、PET-CT X）
- 病理 / 基因检测 X 份
- 出院小结 / 门诊记录 X 份
- 用药记录 X 份
- 其他 X 份
```

对不上的地方要问，不要替用户归类。

### 第 2 步：内容提取

逐份读取内容。**读不出来的（照片太糊、扫描件歪斜、录音）要单独标出来**，写成
`[未能识别——需人工确认]`，不要猜内容，也不要因此中断整个整理。

识别失败时给用户一句可操作的话，例如「这几张重新拍一下，四角对准、光线均匀」。

### 第 3 步：自动分类

按下面的 11 类体系归档。先按关键词快速判断，拿不准的再逐份看内容。

```
患者病历
├── 基本信息（主诉 / 现病史 / 既往史 / 过敏史 / 家族史）
├── 检验指标（血常规 / 生化 / 肿瘤标志物 / 凝血 / 其他）
├── 影像检查（CT / MRI / PET-CT / 超声 / X-ray / 内镜）
├── 病理报告（组织病理 / 细胞学 / 分子病理 / 基因检测）
├── 用药方案（处方 / 化疗方案 / 靶向 / 免疫治疗）
├── 诊疗记录（出院小结 / 门诊记录 / 手术记录 / 治疗小结）
└── 其他资料（医保 / 费用 / 营养 / 护理 / 健康教育）
```

**分类结果展示给用户确认**——分类错了后面全错。

日期尽量提取（`2024-03-15`、`2024年3月15日`、`24/03/15` 都要认）。

### 第 4 步：时间线

按日期排一遍，这是整册病案最有价值的部分：

```
2024-03-15  首诊，确诊（胰腺癌，KRAS G12D）
2024-03-20  基因检测报告
2024-04-01  一线治疗开始：<方案>
2024-07-10  CT 评估：PR
```

展示给用户确认，同一天的按分类分组。**时间线只呈现资料里写明的事实**，
不做「据此推断病情进展」这类判断。

### 第 5 步：生成档案

按用户要的格式输出：Markdown（归档、可版本管理）/ HTML（方便看和分享）/
Word 或 PDF（带去医院复诊）。

如果用户的助手环境能写文件，就写成文件并给出路径；不能写就**直接在对话里给出完整内容**，
让用户自己保存。

### 第 6 步：指出缺口

主动列出「这一类还没有资料」，并说清补它有什么用：

```
还缺（建议下次复诊时补）：
- 影像检查：只有 2024-07 的 CT，缺最近一次复查
- 过敏史：病历里没写，用药前医生会问
- 最近一程化疗方案：只有日期，缺具体药名和剂量
```

---

## 二、增量更新

用户下次再给资料时，**不要从头重做**：把新资料插进已有时间线的正确位置，
分类沿用，缺口清单更新。

同一份资料重复给的情况要能认出来（按内容判断，不要按文件名）。

---

## 三、可以顺手做的事

- 整理完可以接着用「焦虑抑郁量表评估」，把情绪这一维也记进来
- 需要给医生看时，用「决策辅助助手」把那册病案转成"和医生讨论的问题清单"

---

## 四、不要做

- 不要根据资料**推断诊断或分期**——资料里没写的就不写
- 不要把「没找到某项资料」说成「没做过这项检查」
- 不要替换原始资料：整理出的档案是索引，原件始终以医院的为准
- 不要让患者把整理结果当作诊断依据
