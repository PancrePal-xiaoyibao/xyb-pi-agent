# 小胰宝 · 我的资料（`xyb.records`）

把患者散落的检查报告、影像与就诊资料，归到一个**本地**资料库，整理成可追溯的病案索引，并生成患者可读的病情摘要。

## 患者视角它解决什么

- 报告东一份西一份，想找上次的 CT 结果要翻半天
- 想给别人看病情，每次都要口头复述
- 想让 AI 帮忙看看，又担心隐私

## 能力

| 能力 | 形态 | 是否联网 | 是否调用模型 |
|---|---|---|---|
| 导入资料并自动归类 | 命令 `xyb.records.import` + 视图按钮 | 否 | 否 |
| 整理病案（分类/时间线/缺口） | 命令 `xyb.records.organize` + 视图按钮（预览后确认保存） | **否** | **否** |
| 保存病案整理结果 | 视图按钮 → 命令通道 `xyb.records.organize.save` | 否 | 否 |
| 生成患者友好病情摘要 | 命令 `xyb.records.summary` + 视图按钮（预览后确认保存） | 是：把脱敏文本发给你自己配置的模型 | 是 |
| 保存摘要到资料库 | 视图按钮 → 命令通道 `xyb.records.summary.save` | 否 | 否 |
| 资料库位置配置 | 插件设置 `vaultDir`（仅作提示，整理/生成时仍需重新选目录） | 否 | 否 |
| 发送前自动隐藏个人信息 | 规则脱敏（摘要路径始终执行；见下方「数据与隐私」的覆盖边界） | — | — |
| 供助手调用的摘要技能 | 技能 `skills/patient-summary.md`（由助手执行，同样先脱敏） | 仅在使用 AI 时 | 是 |

### 「整理病案」与「生成病情摘要」的区别

这是两条独立路径，请按需选择：

- **整理病案**（`xyb.records.organize`）——**完全在本机完成**。读取文本资料、按 7 类归档、抽取日期排成时间线、指出资料缺口，输出一份**索引**。不联网、不调用模型、不消耗额度，因此可以随时反复运行。
- **生成病情摘要**（`xyb.records.summary`）——需要把脱敏后的文本发给**你自己配置的模型**，会消耗你的额度。产出的是自然语言叙述，适合给人看。

两条路径都是**先预览、确认后才写盘**。

### 文本覆盖边界（重要）

只有 **`.txt` / `.md` 文本资料**会被解析正文。PDF、Word、图片、DICOM 与表格在当前版本**不解析正文**，只计入「未解析」数量；界面与档案都会**如实列出**未能解析的文件清单及原因，避免让人误以为「整理过就等于都读过了」。

档案索引只记录分类、日期与文件名，**不复制原件正文**——原件始终以医院出具的为准。

## 权限说明

| 权限 | 用途 | 风险级 |
|---|---|---|
| `ui.view` | 在右侧工作面板显示「我的资料」 | 低 |
| `fs.read` / `fs.write` | 读取并整理用户选择的资料目录 | 中 / 高 |
| `agent.prompt.inject` | 让助手加载"病情摘要"技能 | 高 |
| `models.list` | 列出可用模型，用于选择摘要所用模型 | 中 |
| `agent.complete` | 生成摘要时调用模型（一次调用，会消耗你的额度） | 高 |

`manifest.fs` 声明的读写作用域是 `userSelected`：只能访问你在本次会话中亲自选择过的目录（`pi.fs.requestDirectory`），插件拿不到目录之外的路径。

## 开发

```bash
# 在仓库根目录校验
pnpm pi-plugin check apps/desktop/resources/plugins/xyb.records

# 离线回归测试
cd apps/desktop && node --test test/xyb-records-organize.test.mjs
cd apps/desktop && node --test test/xyb-records-summary.test.mjs
```

启动应用后：**插件 → 加载开发插件** → 选择本目录。改动会自动热重载；新增权限需要重新加载插件页并确认。

## 数据与隐私

- 资料只存在本地，不上传、不建账号
- **整理病案全程在本机完成**，没有网络请求，也不调用模型
- 生成摘要时会**再次**请你亲自选择资料库目录，未选择则不发送任何内容
- 送出模型前按规则替换电话、身份证、带称谓的姓名与医院名；
  **规则脱敏覆盖不了所有姓名、地址、病历号与邮箱**，界面会提示你自行确认内容可以外发
- 模型输出与整理结果都只用作预览，**确认后才写入**资料库，不会自动保存
- 卸载插件不会删除用户资料
