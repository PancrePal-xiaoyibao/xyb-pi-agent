# 小胰宝 · 智能助手（`xyb.assistants`）

把肿瘤患者常用的助手，绑定成助手**按需加载的技能**。

## 为什么用技能而不是一个大提示词

把 8 个助手的规则塞进一个万能提示词，会导致：上下文被无关规则占满、措辞改不动、出问题查不出是哪段规则导致的。

改成技能后：助手只看到一份**短目录**，患者问营养时才读营养技能全文。技能是纯 Markdown，医生和社区成员可以直接改措辞，不必碰代码。

## 包含的助手

| 助手 | 技能文件 | 做什么 |
|---|---|---|
| 病历助手 | `skills/medical-record.md` | 整理成结构化病情档案（十段式） |
| 影像助手 | `skills/imaging.md` | CT / MRI / PET-CT 报告字段与变化解读 |
| 病理助手 | `skills/pathology.md` | 病理与免疫组化解读（三段式输出） |
| 基因解读助手 | `skills/genomics.md` | 基因/分子检测解读，标注证据等级 |
| 决策辅助助手 | `skills/decision-support.md` | MDT 框架 + 五维评分 + 反幻觉自检 |
| 营养支持助手 | `skills/nutrition.md` | 营养评估、治疗期饮食、症状应对 |
| 心理支持助手 | `skills/psych-support.md` | 情绪陪伴、沟通策略、安宁疗护知识 |
| 并发症助手 | `skills/complications.md` | 红 / 黄 / 绿分级与就医时机 |

> 「临床试验助手」不在这里——它需要联网检索与 `xyb_trials_search` 工具，
> 由 [`xyb.trials`](../xyb.trials/) 提供，权限边界更干净。

## 权限说明

| 权限 | 用途 | 风险级 |
|---|---|---|
| `ui.view` | 右侧「智能助手」视图 | 低 |
| `agent.prompt.inject` | 让助手加载技能 | 高（需用户授权） |

**只有两个权限。** 技能是纯文本，插件本身不读写患者文件、不联网——患者资料由助手自己的文件工具读取，临床数据由 `xyb.trials` 的工具检索。

## 从源提示词继承的硬约束

技能里逐条落地了这些红线（源码见仓库 `XYB-ASSISTANTS.md`）：

- 不出诊断、不给具体处方（不列剂量、疗程、频次、给药途径）
- 不做医院／医生推荐与排名
- 关键结论须标注来源名称 + 年份
- 检索命中不足 2 条高可信来源 → 进入「低证据模式」，只给讨论要点与澄清问题
- 信源分级：🟩 指南共识 / 🟨 高质量研究 / 🟧 临床经验 / ⬜ 患者经验
- 机制未披露就写「未披露」，禁止推断
- 跨瘤种、跨试验数据不外推；多瘤种池数据不机械套用亚组
- 不预测生存期、不判断病情进展速度
- 术语科普每行约 20 字

## 待定事项

源材料里的这几项**没有**直接进入技能，需要你决定：

1. **社群渠道引导**（`pro.xiaoyibao.com.cn` 与公众号）属运营信息，未写入
2. **信仰类箴言**（圣经 / 佛学内容）：改为**按用户语境按需引用**，默认只用非宗教鼓励语
3. **CTV / Veeva 的 MCP 绑定**：本地 `ctv-mcp-server` 可注册为 `contributes.mcpServers`，需要确认启动命令
4. **小铃铛（淋巴瘤）/ 小肺宝（肺癌）**：素材已在手，可复制同一结构另建插件
